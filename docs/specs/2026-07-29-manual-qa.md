**Date:** 2026-07-29
**Covers:** three implementation prompts merged into `main` as `50d5567`, `68f6bf1`, `2ee13f1`, plus the reconciliation commit `a37021d`.
**Verified statically only.** Build clean, `eslint` exit 0, **45 test files / 707 tests passing**. Nothing below has been driven by hand — that is what this document is for.

## 0. Read this first

Four known behaviours that look like defects and are not.

1. **`Detect indentation` overrides tab size, including per-language overrides.** It defaults **on**, and for any file with detectable indentation Monaco's detection beats both the global `editor.tabSize` and a `[rust]` override. To test tab size at all, turn `Detect indentation` off first. This is Monaco's behaviour, not ours.
2. **`Tab groups: group by worktree` produces exactly one group holding every tab.** Every workbench tab collection is already keyed by worktree id, so every tab in a worktree *is* from that worktree. It was built as specified rather than reinterpreted. The axis only earns its keep once a pane can show another worktree's tab — until then this mode is inert. **Candidate for cutting.**
3. **The fuzzy settings filter matches loosely on purpose.** It falls back to subsequence matching over descriptions, so a short query like `font` legitimately reaches unrelated rows. Extra loosely-related results are *not* a bug; a **missing exact-name row** is.
4. **Four settings produce no visible change without a language server**: `editor.inlayHints`, `editor.parameterHints`, `editor.linkedEditing`, and `occurrencesHighlight: All files`. They are wired and live — there is simply nothing to render on a plain text file.

## 3. Activity escalation

The rule under test: *activity is never invisible* (MASTER §7.5.3). A collapsed group is a new hiding place.

| # | Do | Expect | Failure |
|---|---|---|---|

| 3.3 | Expand the group | Chip mark clears; each member wears its own | Both chip and tabs marked (duplicate) |

**Not testable — known dead end.** The `failed` activity signal is unreachable. `src-tauri/src/lib.rs` emits `pty-exit:{id}` with a unit payload, so `noteFinished(id, false)` has no caller. A command that exits non-zero will show as *finished*, not *failed*. Documented at `store/terminalWatch.ts:18`; proposal **A2** in the audit spec fixes it in ~30 lines of Rust. Don't hunt for it.

## 9. New editor settings inventory

~25 new options, by section, with what to look for. `editor.renderLineHighlight` is not strictly new — it moved out of hardcoded chrome into a setting whose default is the old hardcoded value.

**Indentation**
- `editor.detectIndentation` — on: a 2-space file behaves as 2 even if Tab size says 4. **See [§0.1](#0-read-this-first).**
- `editor.bracketPairGuides` — a vertical guide connects each bracket pair
- `editor.trimAutoWhitespace` — Enter (auto-indent appears) then Enter again removes the abandoned indent

**Wrapping**
- `editor.wrappingIndent` — wrapped continuation lines align flush / same / +1 / +2 levels
- `editor.wordWrap` gained `Column` — wraps at the column regardless of pane width, unlike `Bounded`

**Display**
- `editor.renderWhitespace` gained `Trailing` — dots only on trailing whitespace
- `editor.renderFinalNewline` — `On` shows a final empty line, `Off` removes it, `Dimmed` greys it
- `editor.rulers` — enter `80, 120` → two vertical rules; blank removes them
- `editor.renderLineHighlight` — none / gutter / line / both for the current line

**Scrolling**
- `editor.mouseWheelZoom` — ⌘+scroll changes font size
- `editor.scrollbarVerticalSize` / `HorizontalSize` — **partial-live, flagged.** The track resizes live; `monaco.d.ts` marks the slider *thumb* as not updatable through `updateOptions`, so it may keep its old width until the editor is recreated. Not a bug in this change.

**Folding**
- `editor.folding` — off removes fold chevrons and disables folding
- `editor.foldingStrategy` — `Indentation` folds by indent instead of language ranges; visible on a language with a real folding provider
- `editor.showFoldingControls` — always / on gutter hover / never

**Cursor**
- `editor.cursorSurroundingLines` — set 10, arrow toward the viewport edge: it scrolls early, keeping 10 lines below the caret
- `editor.multiCursorModifier` — which of ⌥ vs ⌘ adds a second caret on click

**Suggestions**
- `editor.suggestOnTriggerCharacters` — off: typing `.` no longer opens the widget
- `editor.quickSuggestions` — off: no widget while typing an identifier. Deliberately maps to `{other, comments:'off', strings:'off'}`, so it never suggests inside comments or strings even when on — Monaco's default, preserved because defaults must reproduce today's behaviour
- `editor.acceptSuggestionOnEnter` — `Off` makes Enter insert a newline instead of accepting
- `editor.snippetSuggestions` — where snippets sort, or `None` to hide them
- `editor.inlayHints`, `editor.parameterHints` — **need a language server** ([§0.4](#0-read-this-first))

**Highlighting**
- `editor.occurrencesHighlight` — `Off` stops other occurrences of the symbol under the caret being tinted. `All files` needs a language server
- `editor.selectionHighlight` — off: selecting a word no longer tints its other matches
- `editor.unicodeHighlight` — off: invisible / ASCII-lookalike characters stop being flagged. Test with a non-breaking space or a Cyrillic `а`

**Editing**
- `editor.autoClosingBrackets` — `Never`: typing `(` inserts only `(`
- `editor.autoSurround` — `Never`: typing `"` over a selection replaces rather than wraps
- `editor.linkedEditing` — HTML: editing an opening tag edits the closing one. **Needs a language provider**

Every setting in the list reaches Monaco through `editorOptions()` / `modelOptions()`. None is unwired.

## 12. Themes, density, accessibility

### 12.1 The matrix

All 8 themes × light/dark × 3 densities were reasoned through, and the colour half is **machine-checked** by `src/canvasTokens.test.ts` (14 assertions). The canvas is derived **relatively**, not as ten hand-tuned pairs:

```css
:root       { --canvas: color-mix(in oklab, var(--background) 85%, black); }
:root.light { --canvas: color-mix(in oklab, var(--background) 96%, black); }
```

`themes.css` was not edited at all; the test asserts it contains no `--canvas`. Two ratios rather than one because oklab headroom differs by mode — a 15% mix at L≈0.14 is a much smaller absolute step than at L=1.0. Both darken, so the rule is uniform and no theme needed an exception.

| Theme | Mode | Island L | Canvas L | Δ |
|---|---|---|---|---|
| default | dark | 0.200 | 0.170 | 0.030 |
| default | light | 0.980 | 0.941 | 0.039 |
| **github-dark** | dark | 0.140 | 0.119 | **0.021** |
| **github-light** | light | **1.000** | 0.960 | 0.040 |
| monokai | dark | 0.220 | 0.187 | 0.033 |
| solarized-dark | dark | 0.240 | 0.204 | 0.036 |
| solarized-light | light | 0.970 | 0.931 | 0.039 |
| nord | dark | 0.265 | 0.225 | 0.040 |
| dracula | dark | 0.235 | 0.200 | 0.035 |
| one-dark | dark | 0.240 | 0.204 | 0.036 |

**Test these four first — highest risk, by name:**

1. **`github-dark`** — smallest separation in the set (Δ0.021 at L 0.140). At the bottom of the range a fixed *fraction* yields the smallest *absolute* step. It clears the 0.010 floor and beats the existing `--background`→`--sidebar` step (0.013), but this is the one to eyeball on a real panel. **If it reads flat, drop the dark ratio from 85% to ~80%.**
2. **`github-light`** — the spec's named case. `oklch(1.000 0.000 0)` has no room to rise, so the canvas darkens to 0.960 (≈`#f4f4f4`) — the same order of separation GitHub itself uses between `#ffffff` and `#f6f8fa`. `--background` was not touched.
3. **`nord`** — the *lightest* dark theme; its canvas (0.225) is lighter than `github-dark`'s islands. Nothing wrong, but "recessed" reads weakest as an absolute darkness here.
4. **`solarized-light`** — `--foreground` is only 0.530, the lowest-contrast text in the set. Islands didn't change lightness so text contrast is untouched, but any island/canvas confusion hurts readability most here.

Check each at **compact** density especially — it has the least room for the 6px gaps and 8px inset.

## 13. Do not test — unreachable, unwired, or deliberately unchanged

- **The `failed` activity signal.** Unreachable; see [§3](#3-activity-escalation).
- **`Tab groups: group by worktree`.** Degenerate by construction; see [§0.2](#0-read-this-first).
- **Tab groups in the editor window.** It passes none of the new props and renders its pre-existing strip.
- **Tab groups in snapshots.** Only layout presets carry them; see [§5](#5-layout-presets).
- **Presets in `SnapshotManager`.** Palette-only, deliberately.
- **Keyboard chords for groups or presets.** None were added; `keyboard-shortcuts.md` is unchanged.
- **Custom group colours.** Five only, from existing `--chart-1..5`. No picker, no new CSS variable.
- **Pinned tabs sorting to the front *within* a group.** The pin sort runs before grouping, so it orders ungrouped tabs only.
- **`visibleStripTabIds` and `tabGroupOf`.** Exported from the store barrel, no UI behind them yet.
- **The xterm ANSI palette.** 34 literal hexes, deliberately unchanged and explicitly exempted in `tokenHygiene.test.ts` — an ANSI table is a fidelity decision about someone else's output, not chrome.
- **`.dev-chrome`.** Literal by design so a `make dev` window can't be mistaken for the bundle.
- **`WindowFrame`'s resize strips.** macOS keeps native decorations, so it never renders there.

## 14. Notes for whoever reads this next

**Sequencing hazard, for the record.** The islands branch was cut from `main` *before* tab groups and schema-driven settings merged, so it restyled a tab strip with no group chips and a settings dialog with no JSON pane. The text merge was conflict-free, which is exactly why it needed checking by hand: git had no way to know the two edits met. Two edges were reconciled in `a37021d` — the group chip's geometry and one raw `z-[9999]`. The second was caught automatically by the islands pass's own new `tokenHygiene.test.ts`, which is a good argument for that test existing.

**Three token-hygiene fixes landed beyond the briefs**, because the acceptance criteria asked for the grep and a grep is worthless if it ships red: `monacoTheme.ts`'s `"#00000000"`, `GitSidebar`'s seven hardcoded commit-graph lane hexes (a real improvement — the graph previously ignored all eight themes), and `FindPanel`'s `rounded-[2px]`.

**One silent-degradation path worth knowing.** Lightning CSS emits a `@supports (color: color-mix(…))` guard with `--canvas: var(--background)` as the fallback. On a webview without oklab `color-mix`, the canvas silently equals the island and the shell flattens with no error. WKWebView has supported it since Safari 16.2 and the repo already requires oklch (Safari 15.4), so this is unreachable on the supported platform — but it fails quietly rather than loudly.

**Still unbuilt.** The audit's top three proposals have no implementation prompts yet: **A2** (emit the PTY exit code — ~30 lines of Rust, and the cheapest high-leverage item in the whole audit; it is what makes [§3](#3-activity-escalation)'s dead end testable), **A3** (worktree-level escalation), **A1** (agent runs as a tab kind). See `docs/specs/2026-07-29-workbench-100x.md`.
